# i18n — English ⇄ አማርኛ (Amharic) translation layer

This project ships a self-contained bilingual layer in **`config/i18n.php`**. It is
loaded automatically for every page, because `config/db.php` ends with:

```php
require_once __DIR__ . '/i18n.php';
```

Nothing else needs to be edited to get translation across the whole app.

---

## 1. How the language is chosen

| Mechanism | Detail |
|-----------|--------|
| Toggle links | Visit `?lang=en` or `?lang=am` on any page |
| Persistence | Stored in `$_SESSION['lang']` (default `en`) |
| Switcher UI | A floating `EN / አማ` button is auto-injected into every page (hidden when printing) |
| Current language | `current_lang()` returns `'en'` or `'am'` |

The toggle is processed once, at the top of `i18n.php`, straight from the `GET`
parameter — so it works even on pages that later redirect.

---

## 2. Translating static UI text (the dictionary)

All fixed labels, buttons, table headers, statuses, messages, etc. live in one
English → Amharic map: `i18n_am_map()`.

**To add or change a phrase**, add one line to the map:

```php
'Your English Text' => 'የአማርኛ ጽሑፍ',
```

Rendering is done by an **output-buffer post-processor**:

1. The whole page is buffered (`ob_start`) and flushed at the end.
2. If the language is `am`, `i18n_translate_html()` rewrites **text nodes only**.
3. `<script>` and `<style>` blocks are **never** touched.
4. Only safe attributes are translated: `placeholder`, `alt`, `aria-label`.
5. HTML tags, attribute values, CSS and JS remain byte-for-byte intact.

This means you do **not** have to wrap every string by hand — any phrase that
appears in the dictionary gets translated wherever it is rendered, on every page.

### Using it explicitly in PHP
When you want translated text directly (e.g. building a string in code):

```php
echo t('Payments');        // → "ክፍያዎች" when lang=am, else "Payments"
```

## 3. Translating dynamic database content — `tr()`

Static UI is one thing; values that come from the database (building names,
free-text repair descriptions, etc.) need machine translation:

```php
echo e(tr($lease['building_name']));
echo e(tr($request['description']));
```

`tr($text)` behaviour:

- Detects the script (Ethiopic Unicode range `U+1200–U+137F`). If the text is
  already in the target language, it returns it unchanged (no double-translation).
- **Never translates identifiers**: pure numbers, `INV-12345`, `G-01`, phone
  numbers, etc. are returned verbatim.
- Uses the current UI language as the target (EN→AM when `lang=am`, AM→EN when
  `lang=en`).
- Results are cached in the **`translation_cache`** MySQL table, so each phrase
  hits the external API only once.
- If the API is unreachable (offline / blocked), it **silently falls back to the
  original text** — the app never breaks.

> Personal names are intentionally *not* auto-translated (translating names
> corrupts them). Apply `tr()` only to descriptive content.

---

## 4. Machine-translation backend

- Endpoint: Google's free public `translate_a/single` (gtx) — no API key needed.
- Enabled/disabled via the constant in `config/i18n.php`:

```php
define('I18N_MACHINE', true);   // set false to disable all external calls
```

- **Proxy support:** `i18n_proxy()` auto-detects an HTTP(S) proxy from
  environment variables, then from the Windows registry (e.g. a corporate proxy).
  This is required on networks that block direct outbound access.
- Timeouts are short (5–8 s) and failures are non-fatal.

The dictionary-based UI translation works **fully offline**; only `tr()` needs
the network.

## 5. Installing the cache table

`schema.sql` already contains:

```sql
CREATE TABLE IF NOT EXISTS translation_cache (
    source_hash     CHAR(32) NOT NULL PRIMARY KEY,
    source_text     TEXT     NOT NULL,
    source_lang     CHAR(2)  NOT NULL,
    target_lang     CHAR(2)  NOT NULL,
    translated_text TEXT     NOT NULL,
    created_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

If you imported an older schema, run just that statement once. Without the
table, `tr()` still works but skips caching.

---

## 6. Adding a third language

1. Add a `lang` branch in `current_lang()` / the toggle handling.
2. Add a second map (e.g. `i18n_om_map()`) and extend `i18n_translate_html()`.
3. Add a link to `i18n_switcher_html()`.

The architecture is intentionally simple: one map + one buffer pass = whole-app
translation.
